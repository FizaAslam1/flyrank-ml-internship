📰 Content Refresh Prioritization

A Machine Learning Framework for Content Refresh Decisions

FlyRank ML Internship Capstone • July 2026

Author: Fiza Aslam

📂 Repository: github.com/FizaAslam1/flyrank-ml-internship

Abstract

Content teams managing thousands of pages need to decide which pages to refresh first. Manual review is impossible at scale. This paper presents a machine learning approach to content refresh prioritization using Gradient Boosting on FlyRank search warehouse data. On a time-aware split (January-February 2026 training, March 2026 testing), the model achieves 84.7% accuracy and 90% Precision@50 — a 66% improvement over the hand-rule baseline (24% Precision@50). The output is a ranked action queue with four priority levels and human-review rules. This framework is directional and decision-support — not causal.

1. Introduction

Content teams face a fundamental challenge: with thousands of pages, how do you decide which ones to refresh first? Manual review is impossible. Simple rules (like "refresh pages older than 180 days") achieve only 24% precision — meaning 76% of flagged pages don't actually need refresh.

This paper presents a machine learning solution using Gradient Boosting to rank pages by predicted decline risk. The model learns from three signals — impressions, clicks, and search position — to identify pages likely to decline. The output is a ranked action queue enabling content editors to focus on high-priority pages.

Core Question: "Which page should we refresh next, and why?"

3. Methodology

3.1 Target Definition

Target: is_declining (binary)

A page is labeled as "declining" if:

  • CTR is below median relative to peers (bottom 50%)
  • Has at least some visibility (impressions > 5)
  • 15% random noise added to simulate real-world uncertainty

3.2 Feature Engineering

FeatureDescriptionAvailable Before Prediction?
impressionsTotal GSC impressions (visibility signal)✅ Yes
clicksTotal GSC clicks (engagement signal)✅ Yes
avg_positionAverage search position (ranking quality)✅ Yes
Why only 3 features: CTR was intentionally removed to prevent target proxy leakage. Position alone was found to be nearly useless (0.2% importance) — included for transparency.

5.1 Ranked Actions

✅ KEEPNo actionScore < 0.20Currently healthy

5.2 Human Review Rules

Before acting on any model recommendation:

  1. Check the page manually — does it actually need refreshing?
  2. Verify reason codes match real observations
  3. Check business priorities — important pages may need refresh regardless of score
  4. Skip pages updated in the last 30 days
  5. Sample 5-10 MONITOR pages monthly for quality check

5.3 What Should NEVER Be Automated

  • ❌ Auto-refreshing content (requires human writer)
  • ❌ Auto-deleting pages
  • ❌ Auto-changing titles/URLs
  • ❌ Sending automated alerts to clients
  • ❌ Using as the ONLY input for content strategy

6. Limitations & Honest Framing

⚠️ This analysis is directional, not causal.
  • Time-bound: Model trained on Jan-Feb 2026, tested on March 2026. Performance may vary for other months.
  • Data-dependent: Uses sampled data (50K rows/month). Full dataset may give different results.
  • Not causal: High decline score ≠ "this page will definitely decline." It means "patterns similar to pages that declined in the past."
  • No content quality assessment: Model uses traffic metrics only. Cannot judge writing quality, accuracy, or brand alignment.
  • Threshold-based: Action labels depend on threshold (0.35). Teams should adjust based on capacity.
  • Single-month test: March 2026 is one month. Multi-month testing would strengthen confidence.
  • Safe language: observed / measured / directional / decision-support. No causal claims without experiment.
